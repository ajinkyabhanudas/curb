# Curb threat model v1 (vertical slice only)

Scope: the local engine and CLI in `engine/` at this branch (filesystem store, one rule, no service, no UI). Production concerns from the original plan (tenant authorization, tokens, SSO, sandboxing, signed releases) are out of scope and listed under "Not covered" below. This is a design review of code and tests, not a penetration test. The controls named here were read from the source, and the test files exist in `engine/test/`.

Assets: the verdict and its evidence, the agreement text, the obligation record, the audit log, stored blobs, and the operator's terminal. Adversaries considered: a hostile repository under scan, a hostile or careless editor of files on disk, and a hostile agreement or obligation file.

| # | Threat | V1 control | Verified by | Residual risk |
|---|---|---|---|---|
| 1 | Hostile repository: symlinks, huge files, binaries, hooks, postinstall scripts | `takeSnapshot` never follows symlinks (records link text, status `symlink`), never executes anything, skips `.git` and card-excluded dirs, caps size on the normalized text (1 MiB default; raw size over twice the cap is not read), marks binary and unreadable files. Evaluator maps every symlink to `unknown`, and too-large or unreadable files to `unknown` unless their type is on the never-scanned list; binary content is never analyzed (skipped for never-scanned types and extensionless files, `unknown` under any other extension, so a NUL byte or UTF-16 encoding cannot hide a script). | `snapshot.test.ts`, `snapshot-cap.test.ts`, `evaluator.test.ts` | TOCTOU: the snapshot calls `lstat` and then `readFile` on a path, so a concurrent local writer could swap a regular file for a symlink between the two calls and the target's content would be read as that file. V1 assumes no concurrent writer in the scanned tree. A directory named like a card exclusion, and any directory named `.git`, is skipped at any depth (both disclosed in the card). Reading many files up to the cap is not rate-limited. |
| 2 | Tenant or path traversal | Tenant id must match `^[a-z0-9][a-z0-9-]{0,62}$`; blob hash must match 64 lowercase hex before any path is built. Snapshot keeps hostile file names inside the root. | `store.test.ts`, `snapshot.test.ts` | A pre-planted symlinked tenant directory is followed (see row 6). No authorization layer exists; `--tenant` is a label, not an identity. |
| 3 | Forged or edited obligation | `parseObligation`: exact key set, types, range and quote must match the agreement text, card id and version must match, registry-checked allowlist, id must equal the hash of the content; `verifyObligation` runs again at scan. | `obligation.test.ts`, `scan.test.ts` | The id is a hash, not a signature. Anyone with the agreement can build a valid obligation naming any approver; the approver field is a claim, not an authenticated identity. |
| 4 | Forged or edited result file | `parseResultFile`: exact shape, per-field validation, state invariants; `verifyResultIntegrity` recomputes the result hash and every finding id. `report` and `diff` also check the result against the supplied obligation, agreement and card. | `result-invariants.test.ts`, `report.test.ts` | This is a checksum, not a signature. Whoever can edit a result can recompute the hash and ids, and can stay within the state invariants. Signing is future work. The envelope (operator, times) is not covered by the hash. |
| 5 | Report or terminal injection from repository, agreement or obligation text | Markdown `cell()` renders untrusted text as one code span, escaping pipes and backticks, capping length, escaping control and bidi characters. `safeText` escapes C0, DEL, C1, line separators and bidi characters on terminal output. `stringifyForOutput` escapes the code points `JSON.stringify` leaves raw. | `report.test.ts`, `terminal.test.ts`, `json-output.test.ts` | `card.status` and `card.nonClaims` are trusted input and only get `safeText`. A Markdown viewer with unusual rendering of code spans is not tested. |
| 6 | Audit tampering | Append-only JSONL with a sha256 hash chain (seq, prevHash, hash). `append` verifies the chain first and refuses on corruption; `curb audit` reports OK or CORRUPT (exit 2), and exits 2 when the tenant has no log at all. | `store.test.ts`, `audit-cli.test.ts` | Truncating the tail is undetectable by the chain alone. One writer per tenant is assumed (read then append). Each append reads the whole file (O(n)). A pre-planted symlinked tenant directory is followed. The chain is not signed, so a full rewrite with recomputed hashes passes. |
| 7 | Blob tampering | Blobs are content-addressed. `get` re-hashes and throws `BlobIntegrityError` on mismatch. `put` writes a temp file then renames; `scan` reads the stored result back and fails closed on mismatch. | `store.test.ts`, `recording.test.ts` | Detection only: a tampered blob is refused, not repaired, except that `put` of the same bytes rewrites it. Cross-checking the audit chain against blobs is not automated. |
| 8 | False pass | `pass` needs at least one evaluated file, no findings and no unknown files. File types work as an allowlist: only TypeScript and JavaScript extensions are analyzed, an explicit list of non-code types (docs, data, config, images, fonts, archives, styles, `.sql`, `.graphql`, `.prisma`, `.mdc` editor rules files, compiled and media artifacts, and suffixes such as `.local`; `IGNORABLE_EXT` in `evaluate.ts`) is never scanned, and every other file type gives `unknown` (`unsupported-language` for text, `unreadable` for binary or UTF-16 content), as does an extensionless `#!` script. Binary content is never analyzed; extensionless binaries are skipped. Unparseable, minified (by `.min.js` name, or more than half the file's bytes in lines over 1000 characters), generated, symlinked and over-cap files give `unknown`; a failure while analyzing one file marks that file `unknown` instead of failing the scan. `error` is never a pass and exits 3. State invariants block forged passes at read time. | `evaluator.test.ts` (file-type, declaration-file, per-file failure and minified-share boundary cases), `loop.test.ts` (catalog fixture), `scan.test.ts`, `cli.test.ts` (declaration file scans to a verdict), `result-invariants.test.ts` | Constructs the rule does not model (see row 14) produce `pass` correctly by its own definition but miss real references. Code inside a never-scanned type (for example a provider URL in a `.sql` file) is not seen. The minified threshold is a heuristic: a hand-written file that is mostly long lines reads as `unknown`, and a bundle under half long lines is analyzed (it can only gain findings, not lose them). `pass` is scope-limited evidence. The first real-repository scan showed a concrete false pass (see row 19). |
| 9 | Store placed inside the scanned repo (the scan would read its own output, and the result would depend on prior runs) | CLI resolves real paths and refuses a `--store` inside `--repo`. | `cli.test.ts` | Other tools that write into the repo between runs are not detected. Only the CLI enforces this; the library functions do not. |
| 10 | Nondeterminism | Sorted keys, code-unit ordering, LF normalization, relative paths. `evaluatorVersion` includes the TypeScript version. Timestamps and operator live outside the hash. | `determinism.test.ts`, `recording.test.ts`, `schema.test.ts`, `hashing.test.ts` | `approvedAt` is hashed into the obligation and defaults to the current time unless `--at` is passed, so two confirmations of the same quote differ unless `--at` is fixed. A TypeScript upgrade changes the hash. Locale or filesystem behavior beyond the tested cases is unverified. |
| 11 | Network egress during a scan | Static: no network imports in `engine/src` (`net`, `http`, `https`, `dns`, `fetch(` and `child_process` do not appear; checked with grep on this branch, not by an automated test). Dynamic: a test replaces entry points of `net`, `http`, `https` and `dns` with throwing stubs during a scan (patched: `net.Socket.prototype.connect`, `http.request`, `https.request`, `dns.lookup`). | `scan.test.ts` | Not a real egress denial. The test blocks only those four patched entry points. `fetch`, `net.connect` or sockets created outside the patched prototype, and other egress paths are NOT blocked by the test. Container-level egress denial is deferred to Phase 2. The grep is a one-off check and nothing in CI enforces it. |
| 12 | Evaluator timeout or resource exhaustion | None. The evaluator is synchronous and bounded only by the per-file size cap. | none | A pathological file under the cap could consume CPU. No file-count or total-size limit exists. A worker with a timeout is a Phase 2 item. |
| 13 | Rule (policy card) tampering | `policyCardHash` is recorded in every result. `report` refuses a result whose card hash differs from the supplied card, and `diff --card` refuses unless the card hash equals both results' `policyCardHash`. The shipped card is version 1.3.0. | `report.test.ts` ("refuses a result produced for a different obligation, agreement, card or rule" asserts the `policyCardHash` refusal; "refuses a mismatched --card" asserts the edited card is refused), `delta.test.ts` ("refuses a --card that is not the card both results were produced with"), `card.test.ts` (asserts version 1.3.0 and that edits to `approvedTextPatterns`, `nonClaims` or `registry` change the hash) | The card is an unsigned JSON file and ships as `draft, pending counsel approval`. Anyone who can edit it can change what a scan means. Obligations bind the card id and version, not the card hash, so a card edited without a version bump is accepted by `scan`; only `policyCardHash` in the result shows the change. Two-person release and signed cards are not built. |
| 14 | Registry coverage false negatives | Documented in the card (`falseNegativeRisks`); the report prints the card status, non-claims and exclusions, not the false-negative list. Only TypeScript and JavaScript files are analyzed; never-scanned types are skipped; every other file type gives `unknown`. Gaps found in the final review were closed (any URL scheme, trailing-dot hosts, template heads ending in `?` or `#`, `require.resolve`, import types, gateway prefix case) or newly disclosed in card 1.0.1 (`createRequire(...)('openai')`, `declare module 'openai'`, tagged-template constructor calls, test mocks, path aliases, `.git` at any depth, code in never-scanned types). Card 1.1.0 flags model-identifier literals anywhere in source and grows the registry from 5 to 21 provider ids (packages and hosts verified against npm and public provider documentation, see the measurement doc), and discloses what the literal check misses. Card 1.2.0 adds `openrouter` (22 provider ids) and vendor-documented hosts for openrouter, togetherai, fireworks, deepinfra and moonshotai (CURB-20); hosts not verified against vendor documentation stay listed in `falseNegativeRisks`. Card 1.3.0 (CURB-19) adds provider-named assignments and the `catalog` unknown reason; see row 20. | `recording.test.ts` asserts one false-negative entry exists; `card.test.ts` asserts the registry id list and the 1.1.0 disclosures; `evaluator.test.ts` covers positive, near-miss and lookalike cases, each closed gap, and each new package and host. No test asserts the registry is complete or that the risks reach the reader | Providers not in the registry, dynamic specifiers, identifiers assembled at runtime, bare provider-name strings (`gatewayOrder`, `providerOptions` keys), proxies such as `ai-gateway.vercel.sh`, config files and string-assembled URLs are not flagged. The registry is a hand-kept list and will lag new providers. This is the largest accuracy risk and is only mitigated by disclosure. |
| 15 | Concurrent writers on the audit log | None beyond the single-writer assumption. | none | Two concurrent appends can race and break the chain (detected afterwards as CORRUPT, then `append` refuses). |
| 16 | Overwriting an existing output file by accident or by a planted path | `--out` refuses an existing file unless `--force` (`checkOut`, then `writeFile` with flag `wx`) in `confirm`, `scan`, `report` and `diff`. | `cli.test.ts` (confirm and scan), `report.test.ts`, `delta.test.ts` | `--force` overwrites silently. Output paths are not otherwise restricted. |
| 17 | Prompt injection and LLM risks | Not applicable. V1 has no LLM anywhere in the verdict path or elsewhere. | n/a | Re-open this model before any LLM-assisted intake (plan Phase 3). |
| 18 | Unmeasured behaviour on real repositories | One measurement: `vercel/chatbot` at `c2f8235e`, against a synthetic obligation (`docs/curb/real-repo-measurement-001.md`). | the measurement doc (commands and outputs); not an automated test | One repository is not a sample. Before the fix it gave 4 unknown files of 156 (one `.mdc` rules file, three components with one long line each); after, 0. Other repositories will hit other file types (for example `.lockb`, `.snap`, `.patch`, `.html`), symlinks or over-cap files, each of which makes the whole result `unknown`. |
| 19 | False pass from a model catalog held in literals (found on the real repository) | Before card 1.1.0 only literals passed straight to a declared constructor were checked, so catalog ids such as `"openai/gpt-oss-20b"` reaching `gateway.languageModel(modelId)` through a variable were missed; with the unknown files removed the repository scanned as `pass`. Fixed in card 1.1.0 / evaluator 0.3.0: whole `<prefix>/<slug>` literals with a registered prefix and a digit or hyphen in the slug are findings anywhere in source. | `evaluator.test.ts` (model-identifier literal cases and negatives), `loop.test.ts` (synthetic catalog fixture: FAIL with 3 findings, PASS when allowed, FAIL to PASS delta) | Ids assembled at runtime (for example the gateway's own model list fetched at runtime), read from config, or with a slug lacking a digit or hyphen are still missed, as are provider names held as bare strings such as `gatewayOrder: ["fireworks", "bedrock"]`. The literal check can also flag a string that only looks like a model id. |
| 20 | False pass from per-provider catalogs and bare provider names (found on the second repository) | A copy of `chatbot-ui` with every flagged and unknown file removed scanned as `pass` while catalogs such as `provider: "groq"`, `modelId: "llama3-8b-8192"` remained. Card 1.3.0 and evaluator 0.5.0 (CURB-19) flag a string assigned to a provider-named target (a name ending in `provider` or `providerId`: property, class field, JSX attribute, variable declaration, parameter default or assignment, through `as`, `satisfies`, `??`, `||`, `&&` (right side) and ternaries) that is a registered provider id, and report a file of at least 6 bare model-id values making up at least 20% of its string literals as `unknown` (`catalog`) while still scanning it. The same copy now fails. Still missed: provider-name arrays, `providerOptions` keys, display-name maps, shorthand `{ provider }`, values from variables or concatenation, comparisons, `switch` cases, enum values, names that do not end in `provider`, and catalogs below the thresholds, split across files, padded with other strings or of an unlisted model family; a formatting change alone can move a catalog across the 20% threshold. A catalog of only allowed models is still `unknown`. Login and UI choices (`signInWithOAuth({ provider: "google" })`) and cloud, identity or framework names (`cloudProvider: "azure"`, `dataProvider: "groq"`) are flagged (disclosed false positives). The thresholds rest on one repository. | `evaluator.test.ts` ("provider property values", "catalog-shaped files are unknown"), `card.test.ts` (asserts the 1.3.0 disclosures), `docs/curb/real-repo-measurement-002.md` |

## Not covered by V1

Authentication and authorization, per-tenant encryption, GitHub tokens and App permissions, multi-tenant isolation beyond directory naming, signed releases and results, container sandboxing, secret detection in scanned code, rate limits, backups. None of these exist in the engine.
